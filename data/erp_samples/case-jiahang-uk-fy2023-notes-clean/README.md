### ❌ 主 case notes 包含的"答案线索"

| 编号 | 主 case notes | Agent 由此能直接得到 |

| C1-214 | "...CTA 2009 §1298-1301 不可扣除;应纳税所得额调增 +£12,000" | 法律依据 + 调整方向 + 金额 |
| C1-218 | "...CTA 2009 §1289 实际支付方可扣除;应纳税所得额调增 +£15,000;FY2024 实际支付时转回(DTA £3,750)" | 法律 + 调整 + DTA 金额 |
| C1-219 | "...CTA 2009 §55 未经核定准备金不可扣除;应纳税所得额调增 +£8,000" | 法律 + 调整 + 金额 |
| C1-220 | "...CTA 2009 §1305 预计负债实际发生方可扣除;应纳税所得额调增 +£10,000" | 法律 + 调整 + 金额 |

| C1-104 | "...无 Apprenticeship Levy(全年工资 < £3M 免税额)" | 直接给出 AL = £0 |
| C1-125 | "...£154,000 + £56,000 - £30,000 = £180,000 应税利润 → CT £43,950" | 完整会计利润 → 应税利润调整链 |

### ✅ 本 case notes 仅含业务事实

每行 notes 重写为:
- **谁**:交易方(counterparty 字段已有,notes 补充角色描述)
- **什么**:产品/服务/业务类型
- **多少**:金额(net_amount 字段已有,notes 不重复)
- **何时**:日期(txn_date 字段已有,notes 不重复)
- **凭证号**:发票编号 / 合同号 / 银行回单号
- **付款条件**:账期 / 支付方式
- **业务背景**:为什么发生这笔交易(简洁事实描述)

**不包含**:调整方向 / 法律依据 / 税额计算 / 类型标签 / 答案提示。

### 设计原则(case_summary.json `notes_design_principles` 字段也保留)

1. **notes 仅描述业务事实**(交易方/产品/金额/日期/凭证号/付款条件)
2. **不含纳税调整方向**(不写"调增/调减应税利润"、"应纳税额 +X"、"DTA 确认")
3. **不引用法律条文**(不写"CTA 2009 §1298-1301 不可扣除"、"VATA 1994 第 25-28 条")
4. **不标注类型标签**(不写"税会差异·永久性/暂时性"、"资本免税额 100%")
5. **数字不直接给答案**(不写"基于 14 笔销售重算 £77,565")
6. **tax_code 字段允许保留**(Agent 需要它做 ERP 分类,但不依赖它识别差异)
