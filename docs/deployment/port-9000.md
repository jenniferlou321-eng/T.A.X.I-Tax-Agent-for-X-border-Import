# Deploying the T.A.X.I. Frontend on Port 9000 (with Public Access)

This document is the runbook for putting the React frontend on **port 9000**
of a host and exposing it to the public internet, with the FastAPI backend
continuing to listen on **port 8765**.

```
                  public internet
                         │
              ┌──────────┴──────────┐
              │  public entry point │   e.g. https://tax.example.com
              │   (tunnel / DNS /   │   routed to the host by:
              │    reverse proxy)   │     - Cloudflare Tunnel
              └──────────┬──────────┘     - nginx with a real cert
                         │ :443            - ngrok / frp / ssh -R
                         ▼
       ┌──────────────────────────────────────┐
       │ host                                 │
       │                                      │
       │   :9000   serve_frontend_9000.py ──► frontend SPA (dist/)   │
       │            │                         │                     │
       │            │ /api/*  ◄── same origin │                     │
       │            ▼                         │                     │
       │   :8765   uvicorn  ◄─────────────────┘                     │
       │            (FastAPI + WebSocket /api/agent/ws/chat)        │
       └──────────────────────────────────────┘
```

The frontend always talks to **same-origin** `/api/...`. That is the key
simplification: the public tunnel/proxy only has to forward **two prefixes**
— `/` (to 9000) and `/api`, `/docs`, `/openapi.json`, `/health` (to 8765) —
and the WebSocket handshake just works because `Upgrade` headers flow
through the same connection.

---

## 1. Backend changes (already in this repo)

- `tax_agent/server/main.py` — CORS now allows `http://localhost:9000` and
  `http://127.0.0.1:9000` out of the box. For a real public domain, set:
  ```bash
  export CORS_ORIGINS="https://tax.example.com,https://tax-staging.example.com"
  ```
- `tax_agent/frontend/vite.config.ts` — dev server binds `0.0.0.0:9000`
  and proxies `/api`, `/docs`, `/openapi.json`, `/health` to
  `http://127.0.0.1:8765`. The same `9000` port is used for the production
  preview server.
- `tax_agent/frontend/src/api/client.ts` and
  `tax_agent/frontend/src/pages/AgentChatPage.tsx` — default `API_BASE` is
  now same-origin (empty string), so the same code works in dev, in
  production, and behind a tunnel. Override with `VITE_API_BASE_URL` only
  if the API truly lives on a different host.

## 2. Build the frontend

Node 18+ is required for Vite 8. The original deployment target (CentOS 7
with glibc 2.17) is too old to run modern Node — see the *Known host
limitations* section below. In practice:

### Option A — build on a modern dev machine, ship `dist/` over

```bash
# On your laptop / any Linux with Node ≥ 18
cd tax_agent/frontend
npm install
npm run build         # writes dist/
rsync -avz dist/ user@host:/opt/taxi/tax_agent/frontend/dist/
```

### Option B — build in a container on the same host

```bash
docker run --rm -v "$PWD/tax_agent/frontend:/src" -w /src node:20 \
  sh -c "npm install && npm run build"
```

Either way, the artifact that lands on the host is the static `dist/`
directory.

## 3. Serve the frontend on port 9000

`tax_agent/scripts/serve_frontend_9000.py` is a tiny stdlib-only static
server with SPA fallback (any non-asset 404 → `index.html`) and a
traversal-safe `translate_path`. It is **Python 3.6 compatible**, so it
runs on CentOS 7 out of the box.

```bash
cd tax_agent
./scripts/serve_frontend_9000.sh        # binds 0.0.0.0:9000
# or, for one-off invocation:
python3 scripts/serve_frontend_9000.py --dist frontend/dist --port 9000 --host 0.0.0.0
```

Smoke-test it locally before exposing it:

```bash
curl -I http://127.0.0.1:9000/                    # 200 text/html
curl -I http://127.0.0.1:9000/filings/abc-123    # 200 text/html (SPA fallback)
curl -I http://127.0.0.1:9000/assets/does-not.exist.js  # 404
```

## 4. Run the backend on port 8765

```bash
cd tax_agent
# 1. update start_backend.sh so its hard-coded path is no longer /Users/gtc/...
#    (it currently is — see Known host limitations below).
# 2. or use the path-portable wrapper:
python3 run_backend.py
```

`run_backend.py` already binds `0.0.0.0:8765`. It does **not** need to be
touched for the port-9000 plan.

## 5. Put it behind a public entry point

Pick one. The recipes below all preserve the same-origin model and
forward `/api` from the public host to the backend on 8765.

### 5.1 Cloudflare Tunnel (recommended — free, no port forwarding)

```bash
# install: https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/
cloudflared tunnel login
cloudflared tunnel create taxi
cloudflared tunnel route dns taxi tax.example.com

cat > ~/.cloudflared/config.yml <<YAML
tunnel: taxi
credentials-file: /root/.cloudflared/<tunnel-uuid>.json
ingress:
  - hostname: tax.example.com
    path: /api(/.*)?$
    service: http://127.0.0.1:8765
  - hostname: tax.example.com
    path: /docs(/.*)?$
    service: http://127.0.0.1:8765
  - hostname: tax.example.com
    path: /openapi.json
    service: http://127.0.0.1:8765
  - hostname: tax.example.com
    path: /health
    service: http://127.0.0.1:8765
  - hostname: tax.example.com
    service: http://127.0.0.1:9000
  - service: http_status:404
YAML
cloudflared tunnel run taxi
```

`/api/...`, `/docs`, `/openapi.json`, `/health` go to 8765; everything
else (the SPA and its assets) goes to 9000. Cloudflare Tunnel passes
WebSocket `Upgrade` frames through unchanged, so the chat at
`/api/agent/ws/chat` works.

### 5.2 nginx on the same host

```nginx
server {
  listen 443 ssl http2;
  server_name tax.example.com;
  ssl_certificate     /etc/letsencrypt/live/tax.example.com/fullchain.pem;
  ssl_certificate_key /etc/letsencrypt/live/tax.example.com/privkey.pem;

  # API + docs + health → FastAPI
  location ~ ^/(api|docs|openapi\.json|health)(/|$) {
    proxy_pass         http://127.0.0.1:8765;
    proxy_http_version 1.1;
    proxy_set_header   Host              $host;
    proxy_set_header   X-Forwarded-Proto $scheme;
    proxy_set_header   X-Forwarded-For   $remote_addr;
    # WebSocket support (for /api/agent/ws/chat)
    proxy_set_header   Upgrade           $http_upgrade;
    proxy_set_header   Connection        "upgrade";
    proxy_read_timeout 7d;
  }

  # SPA → port 9000 static server
  location / {
    proxy_pass         http://127.0.0.1:9000;
    proxy_http_version 1.1;
    proxy_set_header   Host              $host;
    proxy_set_header   X-Forwarded-Proto $scheme;
    proxy_set_header   X-Forwarded-For   $remote_addr;
  }
}
```

### 5.3 ngrok (quick demo, not for production)

```bash
ngrok http 9000                        # exposes just the frontend
# For /api support, use ngrok's config file or a paid reserved domain
# that lets you route two ports behind one hostname.
```

### 5.4 SSH reverse tunnel (free, least polished)

```bash
# On the public host you control:
ssh -N -R 0.0.0.0:9000:127.0.0.1:9000 \
        -R 0.0.0.0:8765:127.0.0.1:8765 \
        user@public-host
```

## 6. Verify the public deployment

Once the tunnel/proxy is up:

```bash
PUBLIC=https://tax.example.com

# 1. SPA shell loads
curl -sI $PUBLIC/ | head -1

# 2. SPA deep links resolve (the server falls back to /index.html)
curl -sI $PUBLIC/filings/abc-123 | head -1

# 3. API health
curl -s $PUBLIC/health
# -> {"status":"ok","version":"0.1.0"}

# 4. WebSocket handshake
python3 - <<'PY'
import socket, base64, os
s = socket.create_connection(("tax.example.com", 443))
key = base64.b64encode(os.urandom(16)).decode()
req = (
  "GET /api/agent/ws/chat HTTP/1.1\r\n"
  "Host: tax.example.com\r\n"
  "Upgrade: websocket\r\n"
  "Connection: Upgrade\r\n"
  f"Sec-WebSocket-Key: {key}\r\n"
  "Sec-WebSocket-Version: 13\r\n\r\n"
)
s.sendall(req.encode())
print(s.recv(200).decode().splitlines()[0])
PY
# -> HTTP/1.1 101 Switching Protocols  (or 101 with the CF/ngrok flavour)
```

## 7. systemd unit (optional, but recommended)

Drop this in `/etc/systemd/system/taxi-frontend.service` so the SPA
survives reboots:

```ini
[Unit]
Description=TAXI frontend (port 9000)
After=network.target

[Service]
Type=simple
User=taxi
WorkingDirectory=/opt/taxi/tax_agent
ExecStart=/usr/bin/python3 /opt/taxi/tax_agent/scripts/serve_frontend_9000.py \
  --dist /opt/taxi/tax_agent/frontend/dist \
  --port 9000 --host 0.0.0.0
Restart=on-failure
RestartSec=3

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload
systemctl enable --now taxi-frontend
systemctl status taxi-frontend
```

## 8. Known host limitations (this repo's current state)

- `tax_agent/start_backend.sh` hard-codes the macOS dev path
  `/Users/gtc/Learning/智能会计/finalreport/...` — it **will not work
  on a Linux server**. Use `python3 run_backend.py` instead, which is
  path-agnostic. (TODO: rewrite `start_backend.sh` to derive its path
  from `$(dirname "$0")`.)
- CentOS 7's glibc is 2.17, which is too old for Node 18+ and Vite 8.
  Build the frontend on a modern host (or in a container) and ship the
  `dist/` directory. The static server in `scripts/serve_frontend_9000.py`
  is intentionally Python 3.6-compatible to keep the runtime trivial.
- The dev-only Vite proxy in `vite.config.ts` is a convenience for local
  development. **Do not run `vite dev` in production** — use
  `scripts/serve_frontend_9000.sh` against a built `dist/`.
