## 1. CRITICAL — 2 项

### C1. `submit_vat_return` 在 `bypassPermissions` 下运行(法律风险)

- **File**: `backend/agent/engine.py:123` + `backend/agent/engine.py:324`
- **Finding**: `permission_mode="bypassPermissions"` 是默认设置,文档明确说"approves everything that reaches this step"(`markdown/permissions.md:46`)。对一个会向 HMRC 真提交的报税工具,LLM 一次错误输出就会触发真实提交。
- **Doc**: `docs/superpowers/reference/code-claude-com/agent-sdk/markdown/permissions.md:38-49`
- **SDK**: `claude_agent_sdk/types.py:1634`(`"bypassPermissions"` 定义)
- **Severity**: critical
- **修法**: 改为 `"dontAsk"` + `can_use_tool` callback 拦 submit 工具,把决策权交给前端 WebSocket 的"用户按确认"。**前置**:`routers/agent.py` 要改成 `AsyncIterable[dict]` 喂 `client.query()`(`client.py:173-180` 明确拒绝 string prompt + can_use_tool)。
- **Effort**: L(3-4 天,涉及 WS 重构)

### C2. `submit_*_return` 工具缺 `destructiveHint` 标注

- **File**: `backend/agent/tools.py:269-274` + `backend/agent/tax_knowledge_tools.py:98-131`
- **Finding**: `tool()` 装饰器的第 4 参数 `annotations: ToolAnnotations | None`(`__init__.py:170`)在仓库里**完全没传**。`mcp.md` / `custom-tools.md` 都标注:**应给写操作标 `destructiveHint=True`、给只读标 `readOnlyHint=True`**(`custom-tools.md:250-281`)。
- **Doc**: `markdown/custom-tools.md:242-281`(含 `ToolAnnotations(readOnlyHint=True)` 完整例子)
- **SDK**: `claude_agent_sdk/__init__.py:163,170`(4-参签名)
- **Severity**: critical
- **修法**:在 `_make_tool_wrapper`(`tools.py:216`)接收 meta 后,从 meta 字典里读 `destructive: bool` / `read_only: bool`(`backend/models/agent_tools.py` 已有这两个字段),传给 `tool()` 装饰器。AgentToolSet 抽象类加 `annotations` 字段,UK VAT 6 个工具 + KB 工具都标。
- **Effort**: S(半天,~30 行)

## 2. HIGH — 5 项

### H1. 完全没有 PreToolUse / PostToolUse hooks

- **File**: `backend/agent/engine.py:321-354`(`options_kwargs` 构建)
- **Finding**: 没有任何 `hooks=` 配置项。文档强烈推荐 PreToolUse 用于"block dangerous operations"、PostToolUse 用于"log to audit trail"(`hooks.md:124-128`)。
- **Doc**: `markdown/hooks.md:58-102`(完整 HookMatcher 例子) + `:478-481`(并发 dispatch 注意)
- **SDK**: `claude_agent_sdk/types.py:585-595`(HookMatcher) + `:1760`(ClaudeAgentOptions.hooks)
- **Severity**: high
- **修法**: 注册两个 hook:
  - `PreToolUse` matcher=`"^mcp__tax_agent_.*__submit_"`, 拦 submit 类工具(配合 C1)或追加人类确认 token
  - `PostToolUse` matcher=`".*"`, 写 `backend/services/audit_log.py:67` 的 `record(filing_id, stage, action, detail)`
- **Effort**: S(1 天)

### H2. `session_store.py` 反向 reimplement SDK 公开 API

- **File**: `backend/agent/session_store.py:40-117` + `:120-197` + `:200-220`
- **Finding**: SDK 0.2.95 公开 `list_sessions` / `get_session_info` / `get_session_messages` / `list_subagents` / `get_subagent_messages` / `fork_session` / `tag_session`(`__init__.py:609-613, 643-660`)。仓库手写 JSONL 解析,且**会丢 `parent_tool_use_id`、子 agent 消息、hook 事件**(`session_store.py:160-170` 只读 text + thinking 块)。
- **Doc**: `markdown/sessions.md` + `markdown/session-storage.md`
- **SDK**: `claude_agent_sdk/__init__.py:609-660`
- **Severity**: high
- **修法**: `list_sessions` / `get_session_messages` 改 thin wrapper 调 SDK 公开 API(`routers/agent.py:62-83` 调用处同步改)。`delete_session` 走 SDK 也有(`_internal/session_mutations.py`)。
- **Effort**: M(2 天,需要回归测试)

### H3. `AuditLog` 写好了但 0 接入 agent 路径

- **File**: `backend/services/audit_log.py:24-67`(`record` API) + `grep -rn "AuditLog" backend/agent/` → 0 命中
- **Finding**: `record(filing_id, stage, action, detail)` 已实现,但没有任何调用方。一个报税平台的每一次"AI 工具调用"都应该是审计条目。
- **修法**: 通过 H1 的 `PostToolUse` hook 接入。或者在 `engine.py:434-478` 的 ToolUseBlock 分支调 `audit_log.record(...)`。
- **Effort**: S(半天)

### H4. 零 observability / OpenTelemetry

- **File**: `backend/agent/engine.py:340-353`(`env` 字典)
- **Finding**: 完全没有 `CLAUDE_CODE_ENABLE_TELEMETRY=1` 或 `OTEL_*` env。文档明确说"SDK 不产生 telemetry, 把配置透传给 CLI 子进程;CLI 自带 instrumentation"(`observability.md:23-29`)。
- **Doc**: `markdown/observability.md:66-81`(OTEL_ENV 模板)
- **SDK**: 透传 env 即生效,无代码改动
- **Severity**: high
- **修法**: 加 OTEL_ENV 进 `options_kwargs["env"]`,从 `os.environ` 读 `OTEL_EXPORTER_OTLP_ENDPOINT` 等。同时支持 collector URL 走环境变量。
- **Effort**: S(半天)

### H5. `ResultMessage.usage` / `model_usage` 只读了一次就丢

- **File**: `backend/agent/engine.py:499-505`
- **Finding**: 当前只把 `msg.total_cost_usd` yield 到前端,没累加到任何持久化结构。文档明确说"`model_usage` dict 是 per-model 拆分, 是 T.A.X.I. 这种"按申报计费"的关键数据"(`cost-tracking.md:32-37`)。
- **Doc**: `markdown/cost-tracking.md:130-157`(dedup-by-message_id 累加模板)
- **Severity**: high
- **修法**: 在 `AgentSession`(或专门的 `UsageLedger`)累加,key 用 `(filing_id, model, message_id)` 去重。`Routers` 加 `GET /api/agent/usage/{filing_id}`。
- **Effort**: M(1-2 天)

## 3. MEDIUM — 6 项

### M1. `session_store._get_project_dir` 路径匹配脆弱

- **File**: `backend/agent/session_store.py:17-37`
- **Finding**: 用 `"finalreport-tax-agent" in name` 做 fuzzy match,在多项目开发环境会错匹配;正确做法是 `claude_agent_sdk.project_key_for_directory(cwd)`(`__init__.py:627`)。
- **修法**: 调 SDK 公开函数即可。H2 修完后自然消解。

### M2. `Mock` 模式 return 假数字无防护

- **File**: `backend/agent/engine.py:703-717`(`_mock_chat` 假 9-Box)
- **Finding**: Mock 模式里硬编码 `Box 1  £42,520.00` 等数字,如果生产环境意外走 mock(`API_KEY` 配错),会**给用户看真实感很强的假数字**并让他确认。已在 `_sdk_chat` exception 路径里加 `__agui__: tool_unavailable` 信号(`engine.py:510` 优秀实践),但 mock happy path 没有同等防护。
- **修法**: mock yield 在数字前加 `__agui__: "mock_data_disclaimer"` 事件,前端 banner 强制展示。

### M3. `engine.py` 类型 fallback 不完整

- **File**: `backend/agent/engine.py:40-72`
- **Finding**: SDK 不可用时把 `ClaudeAgentOptions` 替换成 `**kwargs` 吞掉,但 `mcp_servers` 是 `dict[str, McpServerConfig]`;mock 模式下给空 dict 也无所谓,真问题在 import 阶段类型 mismatch 会延后到运行时报错。
- **修法**: mock fallback 加 `if not SDK_AVAILABLE: yield "Mock 模式" + 早 return`,不进入 SDK 路径。

### M4. Engine 异常 fallback 路径丢失 thinking 流

- **File**: `backend/agent/engine.py:507-536`
- **Finding**: SDK 失败 → httpx fallback,httpx 路径**完全没发 thinking delta**(只 yield 纯文本)。用户在 SDK 挂时看不到"AI 思考过程",会误以为 AI 跳过了推理。
- **修法**: `_httpx_chat` 加 `thinking_delta` 处理(Anthropic API 同样有 `thinking: {type: "enabled"}` 选项 + `thinking_delta` 事件)。

### M5. `TaxKnowledgeAgentToolSet` 没 fail-soft(全注册失败即无 KB)

- **File**: `backend/agent/tools.py:347-368`
- **Finding**: KB 工具集任一方法 fail → 全部不注册 → 用户得 0 知识。已经对 `AttributeError` 有 try/except,但其他异常类型(如 `ImportError`)没覆盖。
- **修法**: `except Exception as e` 而不是 `except AttributeError as e`。

### M6. `engine.py` `thinking` 配置 hardcoded `adaptive`

- **File**: `backend/agent/engine.py:338`
- **Finding**: `"thinking": {"type": "adaptive", "display": "summarized"}` 是 SDK 0.2.95 推荐值,但文档说"模型自行决定深度, 不思考的模型把它当 no-op"(`thinking` 相关在 `markdown/agent-loop.md`)。M 系列模型可能直接忽略;生产环境应在 `claude-opus-4-8` / `claude-sonnet-4-6` / `claude-haiku-4-5-20251001` 各自开关。
- **修法**: 改成 per-model 配置,env 读 `ANTHROPIC_THINKING_DISABLED_FOR_HAIKU=1` 等。
